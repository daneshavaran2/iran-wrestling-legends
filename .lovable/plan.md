مشکل اصلی این است که `manifest.json` مسیر ویدیوهای local را نشان می‌دهد، اما خود فایل‌های ویدیو داخل `public/videos` وجود ندارند؛ بنابراین پلیر ابتدا فایل local ناموجود را می‌گیرد، خطا می‌دهد و دیگر به ریموت برنمی‌گردد. یک مشکل دوم هم این است که بعضی ویدیوها `.mov` هستند و روی موبایل/iOS ممکن است حتی با فایل local هم قابل پخش نباشند.

برنامه اجرا:

1. اصلاح resolver ویدیو
   - `resolveBundledVideo` را طوری تغییر می‌دهم که فقط وقتی فایل local واقعاً قابل دسترس است، مسیر `/videos/...` را به پلیر بدهد.
   - برای UI ویدیو، resolver async را استفاده می‌کنم تا قبل از ست شدن `src`، وجود فایل local بررسی شود.

2. اصلاح پلیر معرفی کشتی‌گیر
   - در `IntroVideo` اگر local خراب/ناموجود بود، بدون نمایش خطا به URL اصلی برگردد.
   - `onError` را مرحله‌ای می‌کنم: اول local، بعد remote؛ فقط وقتی هر دو fail شدند پیام خطا نشان داده شود.
   - بعد از Retry، منبع دوباره resolve شود و پلیر reload شود.

3. اصلاح MediaGallery برای ویدیوهای گالری
   - همان رفتار local-first و remote fallback را برای ویدیوهای گالری هم اضافه می‌کنم تا فقط تب معرفی درست نشود.

4. اصلاح اسکریپت bundle
   - اگر download شکست خورد و فایل local وجود ندارد، mapping اشتباه داخل manifest نوشته نشود.
   - manifest فقط برای فایل‌هایی نوشته شود که واقعاً در `public/videos` موجودند.
   - فایل‌های `.mov` هنگام sync به MP4 سازگارتر با وب/iOS تبدیل شوند، یا حداقل مسیر خروجی سازگار تولید شود تا پیام «فرمت پشتیبانی‌شده» کمتر رخ دهد.

5. کنترل PWA/cache
   - چون service worker برای ویدیوها cache-first دارد، مطمئن می‌شوم fallback ویدیو با cache خراب گیر نکند و درخواست‌های local missing به شکل قابل پیش‌بینی fail شوند.

6. اعتبارسنجی
   - با اجرای sync و بررسی `public/videos` مطمئن می‌شوم manifest به فایل‌های موجود اشاره می‌کند.
   - مسیر ویدیوی معرفی را در کد و لاگ شبکه/کنسول بررسی می‌کنم تا دیگر روی فایل local ناموجود متوقف نشود.
